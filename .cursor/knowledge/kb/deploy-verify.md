# deploy-verify · 部署与验收事实

## 部署形态
- 当前 `vercel.json` 用 Vite 构建前台；`/api/*` rewrite 到 Fly `mvstudiopro.fly.dev`。
- Fly：**单机双核** performance-2x，/data 独占卷。禁 `fly scale count 2`（卷分裂）；禁密集 `fly ssh console`（压垮健康检查）。`fly.toml [env]` 会被同名 secret 静默接管。
- DB = Neon Postgres（拍板保留，勿再提迁移）。后端部署与正式前台是两条验证通道，须分别核对；Vercel Preview 或评论检查成功不等于后端编译、正式前台或用户全链通过。

## 合并与部署前检查

本轮已授权终审、修正方案，以及不必要 Vercel 存储清理与 Blob→GCS 迁移；没有合并、推送或部署授权。清理先核对对象与引用，迁移先校验读取兼容和内容一致性；历史发布授权不自动续用。取得对应发布授权后，才执行以下检查。
1. `gh run list --branch main` 无 in_progress Fly Deploy。
2. 同时核对真实任务列表的 queued/running 与相关日志；不能仅凭日志没有输出判空闲。单机换版存在中断风险，恢复与退款按具体任务链分别验证，不笼统声称全站无退款。
3. 存在在途学习、运行中生成或冲突部署时不执行合并/部署；状态无法确认也不执行，不取消用户任务腾窗口。

## 验证口径
- `pnpm check > file 2>&1; echo $?` —— 管道会吞退出码（`| tail` 假绿实锤 #1173）；grep 无命中会毒 pipefail。
- 没跑验证只能说「已实现，未验证」；本地绿不冒充线上验收；疑点未闭环禁止肯定陈述（work-rules 3/23）。
- 浏览器使用用户指定的原窗口/标签页；每次写操作前读取最新状态。超时后停止写操作、做有界只读确认，不猜目标，不以重启或替代窗口规避。
- 历史验收曾观察到 Vercel challenge；本轮不把它外推成所有 HTTP 请求恒为403。按具体入口回执判定，已鉴权只读API可作证据；付费/删除仍需明确授权。不得为了验收降低防火墙保护。

## Fly one-shot 脚本模式
脚本 → base64 → `fly ssh console -C "sh -c 'echo $B64 | base64 -d > /tmp/x.mts && cd /app && npx tsx /tmp/x.mts'"`。base64 仅作脚本传输（见 channels.md 铁律），用即说明。
