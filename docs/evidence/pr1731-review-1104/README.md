## 修复

1. 初选生成或去重后数量不足，原来仍成功结算并按请求数量收费。现在拒收不足批次，沿既有失败同源退款；不自动加购模型请求。同批相同标题即使不同 dedupeKey 也去重。
2. 初选接受模型提供的ID，重复ID会使勾选、恢复和扩写身份混淆。新结果统一使用服务端随机ID，原有草稿ID保留。
3. 手动改标题继续携带旧题样本/评分。实际编辑入口现在清除不再适用的证据、评分和推荐，保留正文；未改标题不丢证据。
4. 扩写直接信任客户端返回的证据及模型回传的证据。现在按平台/窗口从本地Growth库重新读取（每请求缓存），只用客户端样本ID与服务端样本相交，指标/链接/日期均来自服务端；无法核实则没有证据，模型不能补造输出证据。
5. 结算接口返回 ok:false 原来被当作成功处理。现在也调用既有待结算路径，业务已成功不触发退款。账本彻底丢失或双重写失败仍需人工对账，本修复没有另建账务恢复系统。

6. 时间窗口提示改为描述下一轮请求，避免用户编辑需求/窗口后把旧结果标成按新窗口核实。
