## 2. 意图与确认严格分离

意图至少保存 intentId、userId/workspaceId/blockId、operation、规范化输入摘要、创建/更新时间、状态、taskId（可暂缺）。epoch不用于恢复归属；但不因此跳过当前账号核验。保存操作类型，避免编辑/延长/普通生成混认。

inputDigest不是用户批准凭证。服务端从实际请求构造规范摘要，客户端摘要仅早提示。包含模型/版本/工作模式、提示词、图视频音频引用及顺序、时长/分辨率/音频等实际生成参数；只排除真正非语义字段，不按白名单漏字段。不把临时签名变化当内容变化，但保留对象generation等版本信息，复用既有规范化规则。

查询原任务无需重新批准；任何新付费提交仍必须通过当前出站确认。不能把旧epoch确认从磁盘恢复后直接盖章。

## 3. 客户端取得意图与持久化

同一次点击执行生命周期：检查当前scope → 原子于本运行上下文地登记pending意图/Promise → 持久化并回读验证 → 准备提交。登记必须早于第一个会让第二次调用穿入的await。并发调用同scope/同输入复用同一意图，不依赖React disabled更新时机。

持久化以intentId保存独立记录，节点保存当前/历史关联；不要一个node键覆盖掉全部旧在途线索。setItem或回读失败，在POST前阻断并保留旧记录。localStorage不能CAS，不能宣称已解决多标签/跨设备；明确采用何种跨标签协调/服务端意图取得方式并做竞争测试。不允许多标签各生成不同intentId后只靠服务端“同键”去重自称闭合。

用户明确“再次生成”才创建新意图，并重新确认；在pending/submitting/unverified状态下普通重试是恢复原意图，不另建。输入改变时保留原意图供查询，提示旧任务与当前稿不同；不能覆盖原摘要。合法新生成不要被永久去重。

建议语义（映射现有枚举，不强迫另建同义状态）：prepared、submitting、unverified、accepted(taskId)、terminal。客户端超时/断网只进unverified，不能自行标服务器failed。

## 4. 服务端扣费前裁决

必须区分：不存在、占位创建中、已有任务、读失败/损坏、同键输入冲突。禁止catch全部变null。

流程：鉴权并校验请求 → 服务端规范摘要 → 同user+intentId原子占位/读取 → 摘要冲突409且零扣费 → 既有任务返回原task → 创建中返回可查询状态 → 唯一持有创建权者继续扣费/建单。

现有fs.link只保证同文件系统的映射排他，不保证整个创建过程排他。赢家写映射后还没写任务，输家不能因任务缺失就开始补建；进程崩溃恢复须凭可验证的租约/持有者及状态接管，不凭等待几秒猜测。损坏映射不得当新任务。核实际部署目录/卷及多实例边界；无法证明共享原子存储则报告边界，不能宣称跨机器保证。若必须新增数据库约束/迁移，先在改前证据中列出，不更换整套任务存储。

沿用chargeKey：余额扣减与扣费日志的原子机制及唯一冲突读回。不是只依赖findPriorChargeByMarker。占位记录绑定原摘要、taskId、chargeKey和创建阶段，使扣费后建单前崩溃可恢复。恢复核已有扣费，不二扣；终态失败同键仍返回原任务，不能免费重跑。

上游已接受但本地回执丢失：用上游幂等/查询能力对账；供应商不支持时保留待核实，不自动再提交。单个逻辑任务不等于上游只发一次，须另验worker并发与恢复边界。

## 5. 恢复查询与批量

接现有findCanvasVideoTaskByIdemKey能力但修正其错误分类；用户归属取服务器登录态，不信客户端userId。客户端已有taskId先查任务，无taskId按原intentId查。状态接口返回creating/unverified时继续核实，不诱导“重新生成”。已完成恢复原产物，失败保留旧合格take；未知状态不自动退款。

批量依赖产物变化后重新prepare，实际摘要与确认不同则标待重新确认；已提交段继续查原任务，不撤销任务。保存批量游标/等待原因，恢复不会跳过确认。暂停受影响的依赖链，独立段行为按现有产品策略明确，不假设必须整批失败。用户确认新输入后才创建/使用对应合法意图，禁止后台自动确认。

UI必须区分：待确认、正在提交、正在核实、运行中、完成、已确认失败。不要用通用“失败请重试”把未知上游状态变成新单入口。

## 6. 必须一次交齐的测试

1. 真实入口两个并发调用，同意图；服务器一个逻辑任务、一次有效扣费、一次上游提交。
2. 服务端接受后丢HTTP响应，重试/刷新找回原任务，无新扣费或上游调用。
3. 持久化失败/回读不一致：零POST。
4. 同意图不同body（含并发首次请求）：正确409且不多扣；改参考顺序/模式/音频也覆盖。
5. 换账号不能查询或绑定他人任务；当前稿改变不盖掉旧产物。
6. 映射写完任务未写：强制屏障卡住赢家，输家不补建；崩溃恢复另验。
7. 映射损坏/读取失败：不走“未命中→新建”。
8. 扣费成功后建单前中断：同chargeKey恢复，无二扣；含个人/团队已支持分支。
9. 上游接受后记录回执前中断：不得自动二次提交，无法查询则待核实。
10. 多标签竞争不覆盖旧在途记录；明确证明同意图取得机制，而非仅测试覆盖事实。
11. 批量依赖变化：待新确认期间零新增提交，确认后实际body与批准一致。
12. 用户明确再次生成：新意图可合法创建，旧失败同键不重开。

测试要验真实持久化记录与调用次数，不能mock掉fs.link/create任务的核心竞态。数据库原子性用现有可用集成设施验证；无设施明确未验，不能只数扣费spy当数据库证据。反证撤掉关键保护必须因目标原因红，断言专用错误码。
